# Warehouse Bin Management

How warehouse space is organized into zones and bins for inventory storage, picking, and operational workflow.

## Overview

```
INVENTORY LOCATION (Warehouse)
       |
       +-- ZONE: Receiving ---------> Inbound goods staging
       |
       +-- ZONE: Storage ------------> Long-term inventory storage
       |       |
       |       +-- BIN: A-01-01-01 --> Aisle A, Rack 01, Shelf 01, Position 01
       |       +-- BIN: A-01-01-02
       |       +-- BIN: A-01-02-01
       |       +-- ...
       |
       +-- ZONE: Picking ------------> Active pick locations
       |
       +-- ZONE: Shipping -----------> Outbound staging area
       |
       +-- ZONE: Returns ------------> Returned goods processing
```

## Data Model

### WarehouseZone

Zones divide a warehouse location into functional areas.

| Field | Type | Description |
|-------|------|-------------|
| `id` | UUID | Primary key |
| `organization_id` | UUID | Owning organization |
| `location_id` | UUID | Parent inventory location (warehouse) |
| `name` | string | Zone display name (e.g., "Main Storage") |
| `code` | string | Short code (e.g., "STOR", "RECV") |
| `type` | string | Zone purpose (see zone types below) |
| `sort_order` | int | Display ordering |
| `is_active` | boolean | Whether the zone is currently in use |

### Zone Types

| Type | Constant | Purpose |
|------|----------|---------|
| `receiving` | `TYPE_RECEIVING` | Staging area for inbound goods from POs and returns |
| `storage` | `TYPE_STORAGE` | Long-term inventory storage |
| `picking` | `TYPE_PICKING` | Active pick locations for order fulfillment |
| `shipping` | `TYPE_SHIPPING` | Outbound staging for packed orders |
| `returns` | `TYPE_RETURNS` | Processing area for returned merchandise |

### WarehouseBin

Bins are the smallest addressable storage unit within a zone.

| Field | Type | Description |
|-------|------|-------------|
| `id` | UUID | Primary key |
| `zone_id` | UUID | Parent zone |
| `code` | string | Bin code within the zone (e.g., "01-02-03") |
| `label` | string | Human-readable label |
| `aisle` | string | Aisle identifier (e.g., "A") |
| `rack` | string | Rack number within the aisle |
| `shelf` | string | Shelf level on the rack |
| `bin_position` | string | Position on the shelf |
| `max_capacity` | int | Maximum item count (null = unlimited) |
| `current_count` | int | Current items stored |
| `is_active` | boolean | Whether the bin is available for use |
| `barcode` | string | Scannable barcode for the bin |

### Bin Code Format

The full bin code is composed as `{zone_code}-{bin_code}`, generated by the `full_code` accessor:

```
STOR-A-01-02-03
 |    |  |  |  |
 |    |  |  |  +-- bin_position (position on shelf)
 |    |  |  +----- shelf (shelf level)
 |    |  +-------- rack (rack number)
 |    +----------- aisle (aisle letter)
 +---------------- zone code
```

This hierarchical format supports efficient pick path routing by grouping items that are physically close together.

## Key Flows

### 1. Zone/Bin Setup

1. Create a warehouse location (InventoryLocation)
2. Add zones to the location, each with a type, code, and sort order
3. Add bins to each zone with aisle/rack/shelf/position coordinates
4. Optionally set `max_capacity` on bins to prevent overstocking
5. Assign barcodes to bins for mobile scanning

### 2. Bin Assignment

When products arrive (via PO receiving or manual stock adjustment):
1. Products are assigned to specific bins
2. `InventoryLevel` records link products to locations, with an optional `bin_id`
3. Bin `current_count` is updated to reflect occupancy

### 3. Capacity Management

`WarehouseBin::isAtCapacity()` checks whether a bin has reached its maximum:

```php
return $this->max_capacity !== null && $this->current_count >= $this->max_capacity;
```

Bins with `max_capacity = null` have unlimited capacity. This check can be used to prevent over-assignment during receiving or bin transfers.

### 4. Pick Path Optimization

The bin addressing system (aisle/rack/shelf/position) enables pick path optimization:

- Bins within a zone are sortable by aisle, then rack, then shelf, then position
- Pick lists can order items to minimize warehouse walking distance
- The zone `sort_order` field controls the sequence in which zones are visited

A typical pick path visits bins in order: `A-01-01-01` then `A-01-01-02` then `A-01-02-01` (same aisle, then next rack, etc.), moving through the warehouse in a serpentine pattern.

### 5. Barcode Scanning

Each bin has a `barcode` field that supports mobile scanning workflows:
- `scopeByBarcode($barcode)` provides direct bin lookup by scanned value
- The mobile app can scan a bin barcode to confirm the correct pick or put-away location
- Bin barcodes are distinct from product barcodes, identified by their zone-prefixed format

## Integration Points

| System | Integration |
|--------|-------------|
| **Inventory Levels** | `InventoryLevel.bin_id` links stock quantities to specific bins |
| **PO Receiving** | Received items can be assigned to bins during the receiving workflow |
| **Order Picking** | Pick lists reference bin locations for each item to guide warehouse workers |
| **Mobile App** | Barcode scanning supports bin verification during pick, put-away, and cycle count operations |
| **Fulfillment** | Pick path optimization uses bin coordinates to generate efficient walking routes |
| **Zones** | Zone types map to workflow stages (receiving -> storage -> picking -> shipping) |
